What this is

This pool runs the published Uniswap V2 contracts, byte for byte — not a fork, not a rewrite, not a compliance-aware variant. The point is to test the central claim of CSB's design: that enforcing identity beneath the contract layer lets ordinary DeFi deploy unchanged while every participant stays known.

The first half of that claim holds. The second half is more complicated, and the pool below is where you can see why.

What the experiment found

1. It runs. The factory, pair and router deploy with no source change.
2. The pool needed permission — after it existed. Creating the pool moves no tokens, so nothing checks compliance and it succeeds. The first transfer into it fails, because the pool holds no KYC attestation. The council must mark it a system contract, which cannot be done in advance because the pool's address is only fixed at creation.
3. The perimeter holds at the edge. Swapping KHRt out to an address with no attestation reverts. Regulated value cannot leave this way.
4. But pool shares are not regulated. The LP token is an ordinary ERC-20 with no compliance hooks. A pool share — a transferable claim on the pooled KHRt — moves freely to an address that could not receive a single riel directly. Redemption stays blocked, so no KHRt escapes; what escapes is the economic exposure to it.

That last one is not a bug we can patch. It follows from wanting both self-enforcing assets and a contract layer open enough to run unmodified protocols. The perimeter governs custody; composability governs exposure.
